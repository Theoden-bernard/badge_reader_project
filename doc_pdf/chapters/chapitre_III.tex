\chapter{Méthodologie et organisation}

\section{Gestion de projet avec GitHub}

Cette section présente l’approche de gestion de projet adoptée, entièrement centralisée autour de l’écosystème GitHub.  
L’objectif est d’assurer une planification claire, un suivi précis de l’avancement et une traçabilité complète des développements, de la conception jusqu’à la livraison.
\newline
Les outils GitHub sont utilisés à la fois comme support de collaboration, de gestion des tâches et de contrôle qualité, garantissant une organisation structurée et évolutive du projet.
\newline

\begin{for_you}{Mon utilisation de GitHub :}
    \begin{itemize}
        \item \textbf{Dépôt central} : Code source et documentation versionnés.
        \item \textbf{GitHub Projects} : Tableau Kanban pour organiser les tâches.
        \item \textbf{GitHub Actions} : Automatisation des tests et de l’intégration continue.
    \end{itemize}

    \textit{Exemple} :
    J’utilise les \textbf{issues} pour suivre les feature et les \textbf{milestones} pour marquer les étapes clés (ex. : « Livraison MVP »).
\end{for_you}

\subsection{User Stories et estimation de temps}

Chaque \textbf{User Story} est liée à des \textbf{commits}, des \textbf{issues} et des \textbf{milestones} GitHub.
Cela me permet de :
\begin{itemize}
    \item Suivre l’avancement des fonctionnalités.
    \item Garantir la traçabilité des développements.
    \newline
\end{itemize}

\begin{for_you}{Mon tableau Kanban :}
    \textbf{Lien vers le projet} :
    \begin{verbatim}
    https://github.com/users/Theoden-bernard/projects/2/views/2
    \end{verbatim}

    \textbf{Colonnes et règles} :
    \begin{itemize}
        \item \textbf{Backlog} : Idées et fonctionnalités non planifiées.
        \item \textbf{Ready} : Tâches prêtes pour le sprint suivant.
        \item \textbf{In Progress} : Développement en cours (\textbf{max 3 tâches simultanées}).
        \item \textbf{In Review} : Code en attente de validation.
        \item \textbf{Done} : Fonctionnalités livrées et testées.
        \newline
    \end{itemize}

    \textit{Exemple} :
    Une User Story comme *« Créer le système d’authentification »* passe de \textbf{Backlog} à \textbf{Done} en 1 semaine, avec des commits liés (ex. : \texttt{FEAT: add login system}).
\end{for_you}

\section{Versioning GitHub et conventions}

J’ai adopté le modèle \textbf{Git Flow} pour structurer le développement :
\begin{itemize}
    \item Séparation claire entre le code stable (\texttt{main}), le développement (\texttt{develop}), les features (\texttt{feature}) et les correctifs (\texttt{hotfix}).
    \item Utilisation systématique des \textbf{Pull Requests} pour les revues de code.
    \newline
\end{itemize}

\begin{for_you}{Normes GitHub}
    \textbf{Schéma Git Flow :}
    \begin{verbatim}
    main -----------------------------------------------
    |
    +-- develop --------------------------------------
        |
        +-- feature/user-authentication
        +-- feature/project-management
        +-- hotfix/critical-bug-fix
    \end{verbatim}

    \textbf{Conventions de commit :}
    \begin{lstlisting}
    FEAT: add user authentication system (#20)
    FIX: resolve login validation issue (#20)
    DOCS: update documentation (#4)
    TEST: add unit tests for user service (#10)
    REFACTOR: improve code structure (#12)
    \end{lstlisting}

    \textbf{Pull Requests :}
    \begin{itemize}
        \item Toute modification passe par une PR.
        \item Revue obligatoire avant fusion dans \texttt{develop}.
        \item Description claire des changements (ex. : *« Ajout de la validation des mots de passe »*).
        \newline
    \end{itemize}

    \textbf{Pourquoi ? \newline}
    Même seul sur le projet, ces conventions m’aident à garder un historique propre et a isoler les fonctionnalités en développement.
\end{for_you}

\section{Planification et outils de suivi}
J’ai combiné deux outils GitHub pour organiser le projet :
\begin{itemize}
    \item \textbf{Roadmap} : Vue macro des phases clés (ex. : « Conception », « Développement MVP »).
    \item \textbf{Projects} : Pilotage quotidien via un tableau Kanban.
    \newline
\end{itemize}


\begin{for_you}{Ma planification :}
    \textbf{Roadmap} (exemple) :
    \begin{verbatim}
    Phase 1: Conception (4 semaines)
    +-- Analyse des besoins (1 semaine)
    +-- Conception technique (2 semaines)
    +-- Validation architecture (1 semaine)

    Phase 2: MVP (8 semaines)
    +-- Base de données (L)
    +-- Authentification (S)
    +-- Frontend Phoenix (M)
    \end{verbatim}

    \textbf{Configuration de GitHub Projects :} 
    \begin{itemize}
        \item \textbf{Colonnes} : Backlog \myarrow To Do \myarrow In Progress \myarrow Review \myarrow Done.
        \item \textbf{Limites WIP} : 3 tâches max par développeur (pour éviter la surcharge).
        \item \textbf{Automatisation} : Mise à jour des statuts en fonction des commits (ex. : un \texttt{FIX} passe automatiquement en \textbf{In Review}).
        \newline
    \end{itemize}

    \textbf{Bilan :\newline}
    Cette organisation me permet de :
    \begin{itemize}
        \item Conserver une vision globale (roadmap).
        \item Réagir rapidement aux imprévus (Kanban).
    \end{itemize}
\end{for_you}
